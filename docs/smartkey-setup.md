# スマートキー（メインエントランス）セットアップ

## 1. DB
Supabase の SQL Editor で `supabase/migration_smartkey.sql` を1回実行（新規なら `SETUP_ALL.sql` に含まれています）。

## 2. 環境変数（任意）
- `SESAME_API_KEY` … エントランスごとに API キーを入れない場合の共通キー
- 既存の `ROOM_SIGNING_SECRET`（ゲストセッションの署名）を本番では必ず設定

## 3. 管理画面 → 下部「スマートキー」タブ
1. 「エントランスを追加」→ 表示名 / slug / **棟**（Crane Nest など）/ Sesame UUID / シークレットキー / API キー を保存
   - UUID・シークレットキーは Sesame アプリの「オーナー鍵を共有」QR から取得
   - 保存後は秘密鍵は画面に出ません（空欄で保存＝変更なし）
2. 「状態を確認」で接続確認 → 「解錠」（2回押し）/「施錠」で実機テスト
3. QR を「QR画像」または「印刷」（5か国語の案内付きポスター）でエントランスに掲示

## 4. ゲストの流れ
QR → `/key/<slug>` → **名前 + 電話番号の下4桁**（= 予約の PIN。Airbnb iCal の Last 4 Digits から自動設定済み）
- この棟の部屋（客室割り当て先を含む）に泊まる、チェックイン24時間前〜チェックアウトの予約だけ一致
- 同じ4桁が複数あれば名前で絞り込み、絞れなければ「サポートへ」
- 一致すると「エントランス」と「お部屋」（その予約の部屋だけ）を長押しで解錠
- 同時にその部屋の操作パネル `/room/<slug>` も PIN 再入力なしで開けます
- 開始前は「◯◯からご利用いただけます」、チェックアウト後は「期限切れ」になり解錠不可

## 5. 安全対策
- 緊急停止：全物件のアプリ解錠（エントランス・お部屋・既存の部屋パネルの解錠）を即停止。管理者の実機操作は可能
- 本人確認の失敗：同じ端末10分6回 / エントランス全体10分40回でロック
- 操作回数：1予約あたり1分10回まで
- すべての本人確認・解錠・施錠・緊急停止は「入退館ログ」に記録
